# steem-rs

A Rust SDK for the Steem blockchain, built for SteemVault.

The goal is to move signing out of the webview: the wallet should hand a Rust
backend a transaction intent, and the backend should sign it with a key that
never enters JavaScript.

## Crates

| Crate | Description |
| --- | --- |
| [`steem-core`](crates/steem-core) | Protocol types, wire codec, crypto, transactions, memos, authority |
| [`steem-rpc`](crates/steem-rpc) | Blocking JSON-RPC client and broadcast |
| [`steem`](crates/steem) | Umbrella crate re-exporting core + RPC |

The repository is `steem-rs`; the umbrella crate is `steem` so users can write
`use steem::...`.

Published on crates.io:

- [`steem-core`](https://crates.io/crates/steem-core) — [docs](https://docs.rs/steem-core)
- [`steem-rpc`](https://crates.io/crates/steem-rpc) — [docs](https://docs.rs/steem-rpc)
- [`steem`](https://crates.io/crates/steem) — [docs](https://docs.rs/steem)

## Workspace

```text
steem-rs/
├─ crates/
│  ├─ steem-core/   protocol types, wire codec, crypto, tx, memo, authority

│  └─ steem/        umbrella crate re-exporting core + rpc
```

## What works today

`steem-core`:

- `AccountName` validation using Steem's 3-16 character rules.
- `Asset` parsing/formatting for `STEEM`, `SBD`, `VESTS`, `TESTS`, `TBD`.
- WIF private keys (zeroized on drop, no `Debug`/`Serialize`).
- `STM` public keys with RIPEMD160 checksums.
- `ChainId`, transaction digest, compact signatures, public-key recovery and
  verification.
- Steem's canonical-signature rule, with RFC6979 nonce grinding.
- Graphene binary codec (varint, vstring, little-endian primitives).
- Operations: `vote`, `comment`, `transfer`, `transfer_to_vesting`,
  `withdraw_vesting`, `account_update`, `account_witness_vote`, `custom_json`,
  `claim_reward_balance`, `transfer_to_savings`, `transfer_from_savings`,
  `delegate_vesting_shares`, `recurrent_transfer`,
  `set_withdraw_vesting_route`, `witness_update`, `update_proposal_votes`,
  `change_recovery_account`, `request_account_recovery`,
  `cancel_transfer_from_savings`, `account_witness_proxy`.
- `Operation::from_tuple` parses Steem JSON operation tuples.
- Transaction serialization, digest, signing and broadcast JSON.
- Memo encryption/decryption compatible with dsteem (ECDH + SHA-512 +
  AES-256-CBC).
- Authority weight/threshold evaluation, including nested `account_auths`.

`steem-rpc`:

- Blocking JSON-RPC client with typed errors.
- `get_version`, `get_chain_id`, `get_dynamic_global_properties`,
  `get_accounts`, `broadcast_transaction`,
  `broadcast_transaction_synchronous`.

Not implemented yet:

- The full Steem operation set (escrow, proposals, witness set properties,
  comment options, account create, etc.).
- Async RPC and failover.
- Account history, follow/hivemind APIs.
- A multisig signing-room helper.

## Security model

- `PrivateKey` stores the secret in `zeroize::Zeroizing<[u8; 32]>` and never
  implements `Debug` or `Serialize`. `to_wif()` is explicit and returns a
  secret that the caller must handle carefully.
- Signing is local and uses libsecp256k1. The RPC crate only accepts
  `SignedTransaction` values; it never sees private keys.
- Signatures are canonicalized for Steem's acceptance rule.
- The memo implementation matches dsteem's wire format so existing encrypted
  memos decrypt correctly.

## Usage

```rust
use steem::{Asset, ChainId, Operation, PrivateKey, Transaction};

let key = PrivateKey::from_wif("5K...")?;
let tx = Transaction::new(
    1234,
    567_890_123,
    "2026-11-10T12:00:00",
    vec![Operation::Transfer {
        from: "alice".into(),
        to: "bob".into(),
        amount: "1.000 STEEM".parse::<Asset>()?,
        memo: "hello".into(),
    }],
);
let signed = tx.sign(&key, &ChainId::MAINNET)?;
let json = signed.to_json_value();
```

Broadcast with `steem-rpc`:

```rust
use steem_rpc::RpcClient;

let client = RpcClient::new("https://api.steemit.com")?;
let result = client.broadcast_transaction(&signed)?;
```

## Compatibility

The tests include vectors generated by `@steempro/dsteem`:

- transaction bytes: `d204cb50d9...68656c6c6f00`
- transaction digest: `f34cede6...bfb076d2`
- memo ciphertext for a fixed nonce, byte-for-byte
- WIF ↔ `STM` public key round-trip
- signature recovery for the sender key

Run them with:

```sh
cargo test
```

## SteemVault integration

SteemVault now uses `steem-core` through Tauri commands:

- `vault_unlock` decrypts the vault in Rust and returns only account summaries.
- `vault_add_account` / `vault_remove_account` merge keys and re-seal in Rust.
- `vault_public_key` returns the STM public key for a loaded role.
- `vault_sign_digest` signs a 32-byte transaction digest with a loaded key.
- `vault_encrypt_memo` / `vault_decrypt_memo` use the account's memo key.

The webview still uses dsteem to build and broadcast transactions, but it never
receives a private key after import. The remaining `PrivateKey` calls in the
frontend are import-time WIF validation only.

A future step can move transaction construction into `steem-core` as well,
which would remove dsteem from the webview entirely and let the CSP
`connect-src` be tightened to the known RPC hosts.

## Releasing

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo package --list -p steem-core
cargo publish --dry-run -p steem-core
```

Publish in dependency order. `steem-rpc` and `steem` cannot be packaged against
crates.io until `steem-core` is published.

```sh
cargo publish -p steem-core
# wait for the crates.io index to update
cargo publish -p steem-rpc
cargo publish -p steem
```

Publishing is permanent: versions can be yanked, not deleted. Review the public
API and `cargo semver-checks` before publishing.
